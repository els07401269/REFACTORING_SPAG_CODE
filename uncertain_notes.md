# Notes on Uncertain Classifications

**AppTextInput and AppDropdownField as Atoms.** These two widgets wrap Flutter's built-in `TextFormField` and `DropdownButtonFormField`, which already manage their own state internally, such as the text buffer and focus. I still treated my wrappers as Atoms, since they are `StatelessWidget`s that simply pass along a controller or value and a callback. I read the "no state" rule as covering only the state a widget manages itself, not the internal workings of the Flutter widget it wraps.

**ProductForm holding controllers and a `GlobalKey<FormState>`.** This was the toughest decision. Because `ProductForm` is a `StatefulWidget`, it may look like it breaks the rule about keeping local logic without owning core data. I decided that the controllers, the selected category, and the form key together are only the temporary draft of one product being filled in. They are different from the actual catalog (`_products`), which lives only in `CatalogPage`. A stricter reading could move the validators up to `CatalogPage` and pass them down as parameters, so `ProductForm` would only own the controllers. I kept validation inside `ProductForm` because it is specific to the form, and this way the Page doesn't need to know the rules for each field.

**SearchField as a Molecule instead of an Atom.** `SearchField` just combines two Atoms and has no state, so it could fairly be considered a simple Atom-level composition. I still classified it as a Molecule because it serves one clear purpose (searching) that neither of its parts covers alone. This fits the idea of a Molecule as the smallest unit that carries real meaning.

**Introducing a `Product` model class.** The starter code stored products as raw `Map<String, dynamic>` objects. I replaced them with a small `Product` class in `lib/models/product.dart`, mainly so the rule that a Template must never import a data model would have something real to apply to. With plain maps, there is no model that could leak into a Template. This goes beyond the minimum requirement, so I'm noting it here in case a strict reading of "don't change behavior" also covers how the data is represented internally.
